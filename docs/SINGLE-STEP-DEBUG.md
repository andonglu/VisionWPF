# 单步调试功能说明

VisionFlow 编辑器支持对视觉流程进行单步调试：以调试方式启动后，引擎在每个节点执行前暂停，
用户可逐节点观察变量与日志的变化，再决定如何继续。本文档说明其语义、用法与限制。

## 步进语义

| 操作 | 语义 |
|---|---|
| 调试（工具栏"调试"按钮） | 未运行时：校验并以调试方式启动，第一步即暂停在根节点前；暂停中再次点击充当单步（步入）。 |
| 单步（步入，Step） | 恢复执行恰好一个节点，然后在下一个节点前再次暂停；会进入 IfElse 分支与 ForLoop 循环体的子节点。 |
| 逐过程（StepOver） | 当前暂停在复合节点（顺序/IfElse/ForLoop）上时，恢复执行该节点的整个子树且中途不再暂停，停在同一层（或更浅层）的下一个节点；普通节点上等同单步。 |
| 继续（Continue） | 解除所有暂停，自由运行到结束或失败。 |
| 停止（Stop） | 走既有 CancellationToken 取消路径，流程以"已取消"（Skipped）结束。 |

## 用法

1. 编辑或加载流程后，点击工具栏"调试"按钮（运行按钮右侧）。
2. 引擎暂停时：流程树中当前暂停节点以琥珀色高亮并选中；右侧"变量"与"日志"面板刷新为暂停时刻的实时内容。
3. 在暂停状态下点击"调试"（单步）/"逐过程"/"继续"推进执行；点击"停止"取消本次调试运行。
4. 按钮启用规则：未运行时仅"调试"可用；运行中未暂停时仅"停止"可用；暂停中"调试（单步）/逐过程/继续/停止"均可用。

## 实现要点

- 引擎层抽象为 `IFlowDebugHooks`（`VisionFlow.Base/Core/FlowDebugController.cs`），挂在 `FlowContext.DebugHooks` 上，
  由 `FlowNode.Execute` 在每个节点执行前后回调；默认实现 `FlowDebugController` 用 `ManualResetEventSlim`
  在执行线程上阻塞等待，引擎保持同步执行，未挂钩子时零开销。
- 暂停/恢复通过 `FlowProgressKind.DebugPaused` / `DebugResumed` 事件外发（携带节点 Id），现有订阅方不受影响。
- 编辑器侧入口为 `EditorRunSession.StartDebugAsync`，步进控制为 `Step` / `StepOver` / `Continue` / `Stop`；
  暂停现场通过 `IsPaused` / `PausedNodeId` / `ActiveContext` 暴露。

## 限制

- 暂停发生在节点边界，不能暂停在单个工具内部。
- 暂停期间引擎线程被阻塞，流程结构编辑、参数修改、换图与流程切换保持锁定（与运行中一致）。
- 工具预览（CreatePreviewContext 派生的上下文）不继承调试钩子，预览执行永不暂停。
- 停止依赖取消令牌：暂停中点击停止后立即生效；节点执行内部若不响应取消令牌，则需等该节点返回。
- 暂不支持条件断点/命中计数；节点级断点可作为后续扩展（见下）。

## 后续可扩展点

- 断点支持：在 `FlowDebugController` 的暂停判定中加入"断点节点 Id 集合"，流程树上可视化打点，自由运行命中断点即暂停。
- 暂停时变量编辑：在暂停现场允许改写 `FlowContext` 变量后继续执行。
- 运行中切入单步：自由运行中调用 `ArmStepping()` 即可在下一个节点前暂停（"中断"按钮）。

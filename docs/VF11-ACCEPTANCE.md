# VF-11 回归与验收说明

本轮只完善 VF-11 的可重复执行入口和证据记录，VF-08 / VF-09 保留后续处理。
自动回归、样例数值回归、现场效果、UI 交互、长期运行是不同层面的证据，不能相互替代。
项目不提供撤销/重做；取消编辑、未保存提示和保存失败保护仍在验收范围内。

## 1. 原生环境门禁

从仓库根目录运行，需要 .NET SDK、`lib\halcon\halcondotnet.dll`、匹配的 HALCON 原生运行库和有效授权。

```powershell
dotnet test .\VisionFlow.Tests\VisionFlow.Tests.csproj --configuration Debug --no-restore
```

原生用例通过共享的 `RequireAvailable()` 检查环境；环境缺失时明确失败，并包含原因。
不再用 `return` 假装跳过，也不依赖另一个环境用例恰好被选择执行。现有 xUnit 版本和依赖保持不变。

可在具备 HALCON 的机器上验证“缺失环境”路径，无需卸载软件、移动 DLL 或修改系统环境变量：

```powershell
pwsh -NoProfile -File .\VisionFlow.Tests\VerifyMissingHalconRuntime.ps1 -NoBuild
```

该命令需要能加载 net9.0 程序集的 PowerShell 7.5+，且测试项目已经构建。
脚本在独立进程中拦截原生库解析，调用实际的包装释放、图像基线和资源用例，确认它们抛出环境门禁断言。
它不是一次正常图像运行，也不计入正常 xUnit 用例的通过数量。必须使用新的 `pwsh` 进程运行，避免污染后续程序集加载。

输入：`src\Image\razors1.png`；参考结果来自 HALCON 20.11。测试不强制版本相同，跨版本应重新评审参考结果和允许误差。

## 3. 可配置持续运行

`ContinuousRunTests` 对两个样例分别预热 10 次，然后重复执行。流程和输入图像在同一用例内复用，每次运行新建并释放上下文。
每轮检查数值结果和借用输入有效性；CSV 以流式写入保存采样，不将全部采样日志堆积在测试框架内存中。

| 环境变量 | 默认值 | 含义 |
|---|---|---|
| `VISIONFLOW_SOAK_ITERATIONS` | `100` | 每个流程的正式运行次数，正整数；不含预热 |
| `VISIONFLOW_SOAK_SAMPLE_EVERY` | `10` | 每隔多少次采样，正整数；末轮总会采样 |
| `VISIONFLOW_SOAK_MAX_MEMORY_MB` | 未设置 | 采样私有内存峰值相对预热后基线的允许增量，单位 MiB，非负有限数 |
| `VISIONFLOW_SOAK_MAX_HANDLES` | 未设置 | 采样句柄峰值相对预热后基线的允许增量，非负整数 |
| `VISIONFLOW_SOAK_MAX_P95_MS` | 未设置 | 每轮耗时 P95 上限，正有限数，单位毫秒 |
| `VISIONFLOW_SOAK_REQUIRE_BUDGETS` | 未设置 | 设置 `true` 时，三个阈值缺一即失败；只接受 `true` / `false` |
| `VISIONFLOW_SOAK_REPORT_DIRECTORY` | 仓库的 `TestResults\soak` | CSV 输出目录，每个流程使用带时间和随机标识的独立文件 |

小数使用英文小数点。非法值直接失败，不退回默认值。未设置的阈值不会被判定为达标；
报告会明确标记为功能回归，不能把默认 100 次运行称作性能或长期稳定性验收。

以下示例执行每个流程 1000 次，只观察指标，不授予现场验收结论。建议在新的 PowerShell 终端中执行，避免环境变量影响其他运行：

```powershell
$runId = Get-Date -Format "yyyyMMdd-HHmmss"
$env:VISIONFLOW_SOAK_ITERATIONS = "1000"
$env:VISIONFLOW_SOAK_SAMPLE_EVERY = "100"
$env:VISIONFLOW_SOAK_REPORT_DIRECTORY = Join-Path $PWD "TestResults\vf11-$runId"
dotnet test .\VisionFlow.Tests\VisionFlow.Tests.csproj --configuration Debug --no-restore `
    --filter "Category=Soak" --logger "trx;LogFileName=soak.trx" `
    --results-directory $env:VISIONFLOW_SOAK_REPORT_DIRECTORY
```

要启用完整阈值门禁，再设置 `VISIONFLOW_SOAK_REQUIRE_BUDGETS=true` 和三个经过批准的指标阈值。
本文不提供通用“合格阈值”；硬件、流程、运行时版本和目标节拍不同，阈值必须事先确定，而非根据本次结果反向放宽。
实际验收还须满足事先约定的持续时间/次数，不能只依赖用例名称中的“持续运行”。

### 指标口径与报告限制

- CSV 包含 UTC 时间、OS、架构、.NET / HALCON 版本、图像和流程 SHA256、次数、采样间隔及阈值。
- 每个采样点记录私有内存、工作集、托管内存、进程句柄数和最近一轮耗时；基线及收尾前执行 GC，循环内不强制 GC。
- 内存和句柄阈值使用**采样峰值增量**，不是仅看最终值，也不是整个进程寿命内的绝对峰值。增加采样间隔可能漏掉瞬时峰值。
- 私有内存包含测试宿主、托管堆及 HALCON 缓存；句柄数是操作系统进程句柄数，不能直接当作 HALCON 对象数量。
- 每轮耗时包含流程执行、结果断言和上下文释放，不包含周期采样、CSV 写入及收尾 GC。P95 使用全部正式轮次的最近秩法，不包含预热。
- 总经过时间包含采样和收尾开销，不是设备节拍；耗时数组按正式轮次数分配，超长运行需预留记录开销。
- 只有 CSV 最后的 `Outcome=PASS` 才表示这次样例运行完成；中断或失败的 CSV 可能只有部分内容。最终状态以 TRX/测试退出码为准。
- 这些数据来自测试宿主，不是 WPF 窗口或现场设备进程。无法由此证明 GUI 长期开窗、插件预览或相机链路稳定。

## 4. UI 手工验收清单

首选 WPF；仍使用 WinForms 的项目需对其支持的入口单独记录，不能用 WPF 结果代替。未执行项保持“待验”，不适用项须注明原因。
保存失败类场景只在临时目录副本上操作，不覆盖唯一的实际流程文件。

| 编号 | 操作 | 预期 | 当前记录 |
|---|---|---|---|
| UI-01 | 加载两个示例、打开图像、运行并切换输入/输出显示 | 流程成功，显示结果与选中变量一致，无已释放对象异常 | 待验 |
| UI-02 | 通用、专用、实际插件编辑器分别修改参数或模型，预览后取消/关闭 | 原工具配置不变，不新增未保存标记；原有未保存状态保留 | 待验 |
| UI-03 | 未改参数直接确认；只切换文本/下拉焦点；实际改值后确认 | 前两者不置脏，实际改值提交并置脏 | 待验 |
| UI-04 | 配置不存在或无效定位矩阵后预览及正式运行 | 明确报错，不偷偷退回固定位置 | 待验 |
| UI-05 | 较长流程运行期间尝试编辑、新建、打开、换图和关闭；点击停止 | 被保护的入口不可变更运行数据；协作取消后才恢复编辑 | 待验 |
| UI-06 | 临时文件被独占/只读时保存，随后关闭窗口 | 错误可见，原文件与内存配置保留，关闭中止；恢复后可保存 | 待验 |
| UI-07 | 连续运行、切换输出、打开/关闭预览、新建/重新打开流程 | 图像有效、无资源异常；记录宿主内存/句柄趋势 | 待验 |
| UI-08 | 使用实际旧插件二进制，加载旧流程并打开对应编辑器 | 身份、配置、显示与提交兼容；类型转发探针不能代替此项 | 待验 |

## 5. 现场与长期运行记录模板

现场图像和业务标准由集成方提供，不把设备控制、采集、MES 等上层职责加入本仓库。
敏感图像由项目本地管理，证据记录可使用脱敏编号和摘要。

| 记录项 | 待填写内容 |
|---|---|
| 范围与版本 | 工位/用途、日期、执行人与复核人、Git 提交及未提交补丁、宿主类型 |
| 环境 | OS、CPU、内存、.NET、HALCON、插件版本、授权状态、进程标识 |
| 数据集 | 正常/缺陷/边界图像的来源、数量、编号/SHA256；曝光、姿态、光照等工况 |
| 判定依据 | 人工或量具真值、目标输出、单位、允许误差、误检/漏检和节拍标准 |
| 长期方案 | 持续时间/次数、预热、采样间隔、并发负载、事先批准的内存/句柄/耗时阈值 |
| 执行结果 | 实际次数与时长、错误/超时/取消次数、数值偏差及判定统计 |
| 稳定性 | 私有内存/工作集/托管内存/句柄趋势，P95/最大耗时，异常和恢复情况 |
| UI 记录 | UI-01～UI-08 的宿主、结果、复现步骤与截图/日志位置 |
| 证据位置 | CSV、TRX、宿主日志、图像摘要、流程和参数快照 |
| 结论 | 通过 / 失败 / 未执行 / 不适用及原因；不得仅写“没有报错” |

`TestResults` 已加入忽略规则；有价值的报告应另行归档，不依赖本地临时目录长期保存。
在现场数据、UI 操作和持续时间门槛没有完成之前，VF-11 状态保持“部分完成”。

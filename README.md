# VisionFlow 说明

VisionFlow 是一个用于编辑视觉流程的独立流程编辑器项目。它负责提供视觉工具编排、参数配置、流程校验、流程运行调试、变量与日志查看，以及视觉流程文件的加载和保存。

本项目不负责完整设备软件或产线业务闭环。视觉配方管理、产品型号管理、相机采集、外部触发、PLC 通信、结果上报、MES/上位机交互、生产节拍控制等功能，应由上层调用程序负责。VisionFlow 只作为视觉流程编辑与执行组件，被上层项目集成或调用。

## 项目定位

VisionFlow 当前定位为：

- 编辑视觉流程：通过工具箱拖拽或双击添加工具节点，组成顺序、分支、循环等流程结构。
- 配置工具参数：支持引用上游工具输出作为下游输入，并提供部分工具的专用配置页面。
- 校验流程引用：运行前检查必填输入、引用路径、变量类型、分支输出、流程输出等是否合理。
- 调试运行流程：可加载图像后运行流程，查看变量、日志、结果轮廓和节点执行状态。
- 保存和加载流程：将流程结构、节点参数、工具类型和可序列化参数保存为 JSON 文件。

VisionFlow 当前不定位为：

- 视觉配方管理系统。
- 生产运行主程序。
- 相机采集服务。
- PLC/运动控制/IO 通信程序。
- 结果上报或数据追溯系统。
- 完整的产线 HMI。

## 已提供的流程能力

VisionFlow 支持以下流程节点：

- 顺序流程：按节点顺序依次执行。
- 工具节点：调用具体视觉工具，读取输入变量并写入输出变量。
- IfElse 分支：根据条件执行 If 或 Else 分支，并可配置公共输出。
- For 循环：
  - 按次数循环。
  - 按集合循环，可遍历上游数组输出。
- 流程输出：将最终结果统一输出为 `Ok`、`Code`、`Message`、坐标、测量值等上层需要读取的变量。

| 文件 | 说明 |
|---|---|

示例流程默认读取运行时输入 `Input.Image`。在编辑器中可先打开 `src\Image\razors1.png`，再加载示例流程运行。

## 如何编辑视觉流程

1. 启动 `VisionFlow.WpfApp`（推荐）或旧版 `VisionFlow.App`。
2. 从左侧工具箱中双击或拖拽工具到流程树。
3. 在流程树中调整节点顺序，或将节点放入 IfElse 分支、For 循环体中。
4. 选中节点后，在参数面板中配置输入引用。
5. 双击工具节点，打开对应工具的专用配置页面，设置工具参数。
6. 使用“校验”检查流程引用和输出配置。
7. 可打开一张图像后点击“运行”，查看变量、日志和图像叠加结果。

## 如何保存视觉流程

在编辑器工具栏点击“保存流程”，选择保存路径即可。

流程默认保存为 JSON 文件，推荐扩展名为：

```text
*.vflow.json
```

保存内容包括：

- 流程节点结构。
- 节点 ID 和名称。
- 工具类型。
- 工具模块名。
- 工具可序列化参数。
- IfElse 条件和公共输出。
- For 循环配置。
- 流程输出配置。

保存内容不包括：

- 运行时变量值。
- 当前运行日志。
- 上层配方信息。
- 相机、PLC、触发、结果上报等外部设备配置。

## 如何加载视觉流程

在编辑器工具栏点击“加载流程”，选择 `.vflow.json` 或 `.json` 文件即可。

加载后 VisionFlow 会重新构建流程树，并执行一次流程校验。如果发现引用缺失、类型不匹配、输出配置错误等问题，会弹出校验结果。

需要注意：

- 流程中使用的工具类型必须在当前程序或插件目录中可用。
- 插件工具对应的 DLL 需要放在 `VisionFlow.App` 输出目录的 `plugins` 子目录下。
- 如果流程引用了外部文件路径，例如图像、模型、标定文件，上层项目需要保证这些文件路径有效，或在集成时重新配置。

## 与上层项目的职责边界

VisionFlow 输出的是视觉流程能力，上层项目负责设备与业务闭环。

| 功能 | 负责方 |
|---|---|
| 视觉流程编辑 | VisionFlow |
| 视觉工具编排 | VisionFlow |
| 流程保存/加载 | VisionFlow |
| 流程校验和调试运行 | VisionFlow |
| 视觉配方管理 | 上层项目 |
| 产品型号/工位管理 | 上层项目 |
| 相机采集 | 上层项目 |
| 外部触发 | 上层项目 |
| PLC/IO/运动控制通信 | 上层项目 |
| 结果上报 | 上层项目 |
| MES/数据库/文件追溯 | 上层项目 |
| 生产运行界面 | 上层项目 |

上层项目可以加载 VisionFlow 保存的流程文件，并在自己的采集、触发和通信逻辑中调用流程运行接口，将图像或输入变量传入流程，再读取流程输出结果。

- 大规模工具回归测试。
- 完整用户手册。
- 更完整的生产运行界面。
- 更系统的部署和发布包。

当前阶段优先保证流程编辑器、工具编排、流程保存加载和核心工具体系稳定。
